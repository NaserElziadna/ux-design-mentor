# B2B SaaS Design

**Primary Goals:**
- Maximize user productivity
- Support complex workflows
- Enable team collaboration
- Reduce learning curve

**Core Principles (Adapted):**
1. **Efficiency** (Krug - simplicity in context)
   - Minimize clicks for common tasks
   - Keyboard shortcuts
   - Bulk actions
   - Customizable interface
   - Smart defaults

2. **Power user support** (Tidwell - patterns for advanced)
   - Advanced filtering
   - Saved searches/views
   - Batch operations
   - API/integration options
   - Automation

3. **Data clarity** (Don Norman - feedback)
   - Clear data visualization
   - Exportable reports
   - Real-time updates
   - Audit trails
   - Data validation

4. **Team enablement** (Cagan - product thinking)
   - Role-based access
   - Shared workspaces
   - Comments / collaboration
   - Notifications
   - Activity streams

5. **Integration support** (All)
   - Connect with tools users have
   - API documentation
   - Webhooks
   - Data portability
   - Single sign-on

**Critical Metrics:**
- Daily active users
- Feature adoption
- Time to value
- Help requests
- Churn rate

**Common SaaS Patterns:**
- Dashboard (key metrics at glance)
- Tables (with sorting/filtering)
- Modals (for detailed actions)
- Sidebar navigation
- Settings panels
- Admin/team management

**Critical Mistakes to Avoid:**
- ❌ Oversimplifying for beginners at cost of power users
- ❌ Too much UI chrome (toolbars, panels, options)
- ❌ Slow performance
- ❌ Unclear data relationships
- ❌ No bulk/batch operations
- ❌ Insufficient keyboard support

**Testing Approach:**
- Watch power users work
- Time-on-task testing
- Feature adoption tracking
- Help request analysis
- Interview long-term users
