# UX Research: Practical Techniques for Designing Better Products - Brad Nunnally & David Farkas

Scientific research methods for understanding users, validating designs, and making evidence-based decisions.

## Research Foundation

Good UX decisions are based on evidence, not assumptions.

Research answers:
- Who are our users?
- What are their needs?
- What problems do they face?
- Does our solution work?
- How can we improve?

## Research Methods

### Qualitative Research
Understanding the "why" behind behavior.

**Methods:**
- **User Interviews** - Direct conversation about experience
- **User Testing** - Observe users attempting tasks
- **Ethnography** - Observe users in natural context
- **Focus Groups** - Group discussion of topics
- **Card Sorting** - Understand mental models
- **Tree Testing** - Validate navigation structure

**When to use:** Early design, understanding problems, exploring possibilities

**Sample size:** 5-8 participants often sufficient to find patterns

### Quantitative Research
Understanding "how many" and "how much."

**Methods:**
- **Surveys** - Collect responses from many users
- **Analytics** - Measure actual behavior
- **A/B Testing** - Compare approaches scientifically
- **Eye Tracking** - Measure visual attention
- **Heatmaps** - Show interaction patterns
- **Metrics** - Quantify user satisfaction

**When to use:** Validating assumptions, measuring impact, tracking changes

**Sample size:** Larger samples needed (30+ for significance)

### Mixed Methods
Combining qualitative and quantitative.

**Approach:**
- Understand problem qualitatively
- Generate hypotheses
- Test quantitatively
- Explore results qualitatively
- Iterate

**Example:** Interview users (qualitative) → Run survey (quantitative) → Follow-up interviews (qualitative)

## Research Planning

### 1. Define Research Questions
What do you want to learn?

- What is the user's main goal?
- What problems do they face?
- How will our solution help?
- Does our solution work?

### 2. Choose Method
Which method best answers your questions?

| Question | Method |
|----------|--------|
| Why do users behave this way? | Interviews, Ethnography |
| How many users face this problem? | Surveys |
| Does our design work? | User Testing |
| How do users think about structure? | Card Sorting |
| Which design works better? | A/B Testing |

### 3. Recruit Participants
Get right people to participate.

**Characteristics:**
- Represent target users
- Have relevant experience
- Can articulate needs
- Available for research

**Recruitment:** Screener surveys, user panels, ads, referrals

### 4. Create Research Plan
Document your approach.

**Includes:**
- Research questions
- Method and sample size
- Participant criteria
- Tasks/questions
- Data collection method
- Analysis approach
- Timeline

### 5. Conduct Research
Execute with rigor.

**Best practices:**
- Minimize bias
- Take thorough notes
- Record (with permission)
- Remain neutral
- Ask follow-up questions

### 6. Analyze Data
Find patterns and insights.

**Qualitative analysis:**
- Code responses into themes
- Find patterns across participants
- Identify critical insights
- Build understanding

**Quantitative analysis:**
- Calculate statistics
- Compare groups
- Test significance
- Draw conclusions

### 7. Report Findings
Communicate clearly.

**Include:**
- Research questions
- Method and sample
- Key findings
- Supporting evidence
- Recommendations
- Limitations

## Research Methods Detail

### User Interviews
Direct conversation with users.

**Goals:**
- Understand user context
- Explore problems
- Discover motivations
- Test ideas

**Tips:**
- Ask open-ended questions
- Listen more than talk
- Avoid leading questions
- Dig into interesting answers
- Record if possible

### User Testing
Watch users attempt tasks.

**Setup:**
- Recruit 5-8 participants
- Create specific tasks
- Observe without helping
- Take notes
- Ask clarifying questions

**Metrics:**
- Task completion rate
- Time to complete
- Errors made
- Satisfaction
- Usability issues

### A/B Testing
Compare two approaches scientifically.

**Process:**
1. Create two versions
2. Split users randomly
3. Measure outcomes
4. Analyze statistically
5. Implement winner

**Requirements:**
- Sufficient traffic for significance
- Clear success metric
- Random assignment
- Statistical analysis

## Data Analysis

### Coding Qualitative Data
Organize themes from research.

**Process:**
1. Read through all data
2. Identify patterns/themes
3. Code responses
4. Organize by theme
5. Find key insights

**Example themes:** Pain points, workarounds, mental models, motivations

### Statistical Significance
Ensure findings aren't just chance.

**Concepts:**
- **Sample size** - Larger = more reliable
- **Confidence level** - Usually 95%
- **Margin of error** - Usually 5%
- **P-value** - <0.05 = significant

### Affinity Mapping
Organize insights into patterns.

**Process:**
1. Write findings on cards
2. Sort by theme
3. Group related items
4. Find patterns
5. Name categories

## Research Ethics

### Informed Consent
Participants understand what they're doing.

- Explain research purpose
- Describe what they'll do
- Explain data use
- Get permission
- Allow exit without penalty

### Privacy & Confidentiality
Protect participant data.

- Don't share personal information
- Use pseudonyms
- Secure recordings
- Limit access
- Delete data when done

### Beneficence
Research should benefit participants or users.

- Does this help users?
- Is this ethical?
- Are risks acceptable?
- Is data being misused?

## Common Research Mistakes

### Mistake 1: Not Recruiting Right Users
Talking to easy-to-reach people instead of target users.

**Fix:** Define target user characteristics, recruit specifically

### Mistake 2: Leading Questions
Asking questions that suggest desired answer.

**Fix:** Ask open-ended, neutral questions

### Mistake 3: Too Few Participants
Treating 3 interviews as representative.

**Fix:** Continue until patterns emerge (usually 5-8)

### Mistake 4: Researcher Bias
Seeing what you expect to see.

**Fix:** Ask follow-up questions, take thorough notes, involve others in analysis

### Mistake 5: Not Acting on Results
Conducting research but not changing product.

**Fix:** Make research actionable, track recommendations

## Evaluation Framework

- [ ] Have you clearly defined research questions?
- [ ] Is the method appropriate for questions?
- [ ] Are participants representative?
- [ ] Have you minimized bias?
- [ ] Is sample size adequate?
- [ ] Have you analyzed rigorously?
- [ ] Are findings supported by evidence?
- [ ] Are recommendations actionable?

## Key Takeaway

> "The most important research is the kind you actually use." - Brad Nunnally

Good research:
- Starts with clear questions
- Uses appropriate methods
- Recruits relevant participants
- Analyzes rigorously
- Produces actionable insights
- Gets implemented

Research without implementation is just academic.
