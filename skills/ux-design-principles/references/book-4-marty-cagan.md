# Inspired - Marty Cagan

How product leaders discover what customers actually need and build teams that deliver it.

## Core Insight: Discovery Before Delivery

Most teams build what was requested, not what's needed. Discovery happens before building.

**Discovery**: What should we build?
**Delivery**: How do we build it well?

Most time is spent on delivery; success depends on discovery.

## The Product Team

Effective teams include:
- **Product Manager** - Discovers what to build
- **Designer** - How it should work and look
- **Engineers** - Building high-quality solutions
- **Data/Analytics** - Measuring results
- **Other specialists** - Domain experts as needed

All must work together from start to finish.

### Product Manager Role

Responsible for:
- Understanding customers and market
- Defining problems worth solving
- Validating solutions with users
- Defining success metrics
- Measuring results

Not responsible for:
- Telling engineers how to code
- Telling designers how to design
- Creating features just because someone asked

## Discovery Process

### 1. Problem Discovery
Understand the actual problem users face.

- Observation: Watch users work
- Interviews: Ask about challenges
- Data: What are users struggling with?
- Metrics: Where are pain points?

### 2. Solution Discovery
Explore potential solutions.

- Brainstorm options
- Prototype early concepts
- Test with users
- Iterate quickly

### 3. Validation
Confirm the solution works.

- User testing with prototypes
- Measure against success metrics
- Gather quantitative data
- Run small pilots if possible

### 4. Planning
Prepare for delivery.

- Break solution into buildable pieces
- Define dependencies
- Estimate effort
- Plan timeline

## Key Concepts

### OKRs (Objectives and Key Results)
Clear goals guide product work.

- **Objective**: What are we trying to achieve? (qualitative)
- **Key Results**: How will we know if we succeeded? (quantitative, measurable)

Example:
- Objective: "Designers feel confident using our tool"
- Key Results: "80% of new users complete first project" & "Net Promoter Score > 50"

### User Stories
Description of functionality from user perspective.

Format: "As a [user type], I want [capability], so that [benefit]"

Example: "As a designer, I want to quickly reset my password, so that I can regain access if I forget it"

### Prototyping
Rapid experimentation to test ideas.

- Paper prototypes: Concepts and flows
- Wireframes: Layout and structure
- High-fidelity mockups: Visual design
- Interactive prototypes: Feel and interaction
- Minimum viable product: Real solution for validation

### Metrics
Measure what matters.

- **Adoption**: Are users using it?
- **Engagement**: How often/deeply?
- **Retention**: Do they keep using it?
- **Satisfaction**: Do they like it?
- **Business impact**: Revenue, costs, etc.

## The Product Mindset

### Evidence Over Opinion
Decisions based on data, not politics.

- Test assumptions
- Measure results
- Follow evidence
- Question beliefs

### Users, Not Features
Focus on solving problems, not shipping features.

- "This solves user problem X" vs "We shipped feature Y"
- Fewer features that solve problems beats many features
- Quality of solution matters more than quantity of features

### Iterate, Don't Predict
You can't predict the future; learn instead.

- Release early versions
- Gather feedback
- Improve iteratively
- Measure results

### Team Over Process
People matter more than process.

- Hire great people
- Empower teams
- Remove obstacles
- Let them figure out how

## Evaluation Framework

- [ ] Did you discover the actual problem?
- [ ] Have you validated with users?
- [ ] Is success measurable?
- [ ] Is the team aligned?
- [ ] Are you measuring results?
- [ ] Are you iterating based on data?
- [ ] Does the solution solve the problem?

## Key Takeaway

Success comes from:
1. Discovering what customers actually need
2. Building teams capable of delivering
3. Validating solutions before full investment
4. Measuring results and iterating

Not from: Building what was requested, executing to plan, shipping features.

> "Ideas are cheap. Execution is everything." - Marty Cagan (via Steve Jobs)
